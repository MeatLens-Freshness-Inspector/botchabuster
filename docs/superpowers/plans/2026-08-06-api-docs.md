# Developer API Docs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add a developer-only API Docs workspace that documents all 53 registered `/api` operations by category and executes them with Swagger-style forms and Postman-style request/response tooling.

**Architecture:** Keep the API catalog and request tooling in focused frontend modules. The catalog is a typed OpenAPI-like document containing one operation per backend route; React components consume it but do not construct requests. A generic executor builds requests against the configured API base URL, delegates auth and CSRF transport to existing helpers, normalizes responses, and stores sanitized request history locally.

**Tech Stack:** React 18, TypeScript, Tailwind CSS, lucide-react, existing shadcn UI components, Node's `node:test`, `tsx`, `@testing-library/react`, and the existing `apiRequest`/`authCache` utilities.

## Global Constraints

- Document all current `/api` operations: 14 auth, 2 analysis, 5 access-code, 5 inspection, 8 profile, 1 statistics, 1 upload, 1 chat, 3 market-location, 2 audit-log, 2 developer-options, 6 developer-dashboard, and 3 user-chat operations.
- Categorize operations by route namespace and display the category on every operation.
- Keep API Docs inside the developer-only workspace; regular administrators must not render or fetch it.
- Use the configured `API_BASE_URL`; never expose arbitrary external URL execution.
- Use existing cookie/Bearer authentication and CSRF injection behavior.
- Never persist access tokens or CSRF tokens in history or editor state.
- Require confirmation before DELETE operations.
- Support `none`, `json`, `urlencoded`, and `form-data` request body modes.
- Use `apply_patch` for all manual edits and commit each reviewable slice.
- Do not alter the unrelated `frontend/src/lib/reports/pdf/reportCharts.ts` change.
