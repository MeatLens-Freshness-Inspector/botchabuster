# Model Calibration

Model calibration asks whether a reported confidence is trustworthy. A calibrated model is correct about as often as it says it is: predictions near 80% confidence should be correct about 80% of the time when evaluated against reliable labels. Calibration is different from accuracy, which measures only the overall fraction of correct predictions.

## Controlled calibration data

The Model Calibration surface uses imported, labeled validation or test predictions. The application stores normalized prediction rows, not raw images or training datasets. Each row contains a sample ID, ground-truth class, predicted class, confidence, class probabilities, and optional model-version provenance.

Imports are versioned ZIP files with exactly these logical entries:

```text
calibration-package.zip
├── manifest.json
└── predictions.jsonl
```

The supported manifest schema is `meatlens.calibration.v1`. The training repository’s evaluation and final-validation stages produce this artifact. A package must be generated by the ML evaluation pipeline; production inspection records are not a substitute for controlled labels.

## Metrics and diagram

MeatLens uses 10 confidence bins with left-inclusive, right-exclusive boundaries:

```text
[0.0, 0.1), [0.1, 0.2), …, [0.9, 1.0]
```

For each non-empty bin, `confidence` is the mean predicted confidence and `accuracy` is the observed fraction of correct labels. Expected Calibration Error is:

```text
ECE = Σ (number of samples in bin / total samples) × |mean confidence − observed accuracy|
```

The reliability diagram plots mean predicted confidence against observed accuracy and overlays the ideal `y = x` diagonal. Points below the diagonal indicate overconfidence; points above it indicate underconfidence. Empty bins remain empty and are not allowed to imply a measurement.

For all classes, Brier Score is the mean squared error between the multiclass probability vector and one-hot ground truth. With a selected class, it is the binary score for that class probability and one-vs-rest ground truth. Lower values are better.

The page always shows the labeled sample count beside these metrics. Null metrics mean that no labeled samples were available for the selected filters.

## Filters and provenance

Class and model-version filters are populated from stored calibration metadata and application model metadata. No model version is invented when an evaluation artifact does not provide one. Class names are read from the imported data and existing model metadata rather than hard-coded into the analytics calculation.

The original AI prediction and confidence on an inspection remain unchanged when a dispute is approved. The calibration tables use controlled package rows; the production monitoring tables use the original inspection values.

## Field Confidence Monitoring

Field monitoring is intentionally separated from controlled calibration. It groups production inspections by their original AI confidence and reports pending, approved, and rejected disputes. A dispute rate uses only rows for which the denominator is available. These values describe observed workflow signals, not model accuracy:

- an undisputed prediction has not been experimentally verified as correct;
- an approved dispute records a review outcome, but its interpretation depends on the existing review workflow;
- a rejected dispute is not automatically established ground truth.

Inspection confidence is persisted in MeatLens as a percentage from 0 to 100. The repository converts it to 0–1 only at the analytics boundary; the persisted original value is never overwritten. The focused investigation list uses the centralized 80% high-confidence threshold and links to the existing History inspection detail interface.

## Reports and audit

JSON and CSV dashboard exports reuse the loaded calibration analytics response, including controlled metrics and field-monitoring observations. They do not recalculate metrics in the browser. Import actions create an audit event containing the actor, source hash, model provenance, and sample count; individual prediction rows are not copied into the audit log.
